## Accepted engineering changes

1. **Unread response bodies retain uncertainty.** A paid request could receive HTTP headers and then lose its response stream before the accepted job ID was read. Previously the raw exception became an ordinary failed job, without the possible-charge warning. It was not automatically resent. The shared client now normalizes both fetch and response-read failures into transport errors. An unread body uses status0 for queue classification, retaining the real HTTP status only as metadata. Thus unread429 headers cannot accidentally authorize a retry. Paid requests become `lost`, preserve their receipt and show the existing possible-charge/no-resend message; transient free GETs can retry. Parsed accepted-ID precedence and known parsed rejection behavior remain unchanged.
2. **Cached optional arrays are owned copies.** `extractOnce` now copies `stencil` and `cut` along with the already copied layer and mask. Two maintained tests deliberately mutate returned arrays and reevaluate the same draft. Both failed before the fix. This is a low-severity cache ownership defect, not a demonstrated live containment exploit.
3. **Exact-coordinate rejection is explicit.** A one-pixel provider redraw can be registered on the old unbounded skeleton route. The stencil route intentionally keeps raw coordinates because moving them could cross protection. Its existing G10 misregistration failure is now documented and asserted as a hard QA failure; it was not weakened to make the new route look better.
4. **Keep correct provenance and clarify diagnostics.** Restored drafts still validate their saved mask blobs; the current accepted-item request still supplies its exact submitted mask. A changed valid-mask regression now demonstrates same-draft/result cache invalidation. Helper wording no longer suggests those two correct paths conflict. `stray`/`strayPx` comments now describe extraction/cleanup/permission removals rather than pretending they are a semantic count of unwanted pixels. No new persistent metric or manifest schema was introduced.

Code is limited to `app/src/lib/pixellab/client.ts`, extraction/cache code and comments in `app/src/lib/items/{run,items}.ts`, and the existing manifest field's comment. New cases extend existing unit-test files. No dependency, backend, model, retry UI, production quality threshold, API generation plan or Studio default changed. A quality failure still does not authorize another paid attempt.

Implementation commit: `0865c0b6` (`fix: preserve paid transport uncertainty and isolate extraction caches`). The compact [reconciliation results](2026-11-02-joint-review-results.json) record verification, disposition and unchanged billing separately from the historical campaign checkpoints.

## Scope, timing and the owner's decisions

The owner already stated that equipped professional-looking animation is a goal. Asking whether it is a goal again is not a prerequisite to these engineering fixes. The supported conclusion is that the current equipped attack is unqualified, not that the project must abandon it or silently disable existing attacks.

Likewise, a production MCP integration, a prepared-art product and new public grip-family UX are separate future scope decisions. None is needed to complete these fixes. The existing Studio defaults remain intact. A new internal frozen-body asset must retain its own identity; it is never silently inserted as an aligned replacement of an existing body.

No further paid experiment is scheduled. The current pilot is196/200 held, with equipment175/175; another25-unit reservation cannot fit unchanged stage rules. The owner's remaining allowance is still authorized, but it is not a reason to bypass holds, reset gates or automatically add Claude's proposed replication. There is no need to ask for the same budget again. A later materially different experiment would need a coherent offline target, independent negative controls, explicit allocation and predeclared stop criteria. Palette snapping may separate recoloring from geometry in older controls, but cannot recover missing silhouettes/fingers or remove skin semantics; it is not a prerequisite to finishing this engineering phase.

“Offline only because Blender is GPL” is not a valid architectural limit on an independent browser3D renderer. The real barriers are fitted art, rigging labor, style fidelity and product scope. Similarly, stable sampled toes do not establish every aspect of contact, weight transfer or continuous timing, even in an in-place flipbook. These corrections do not authorize a new renderer project.
