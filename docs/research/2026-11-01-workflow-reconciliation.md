## Application improvement: preserve the raw grip-risk observation

The existing production G3 check already measures key-colored output outside the body. However, posed output is first registered, a one-pixel pose tolerance is allowed and production posed evaluations use a 5% global share. The failed frame's strict unaligned share is approximately 2.90%, so passing G3 cannot establish that a small but critical hand stayed correct. Lowering that global threshold would not identify hands and could reject ordinary redraw quantization.

The application now records an **informational held-item observation**, before registration or extraction, when key-colored pixels appear where the exact frozen base was transparent. It reuses the existing key-color predicate, counts the raw pixels and preserves their native padded output bounding box. When the requested hand track is available, metadata also records nearest-wrist distance; missing hand evidence is not converted into a measured zero. The transient pixel mask stays in memory, while compact observations persist in per-cell/per-clip QA and survive acceptance, reload/export and replacement of other clips.

An initial implementation made this a warning. The frozen-output benchmark showed that every held clip in its sword/axe/bow cases triggered it: warning counts rose 3 to 9, 1 to 7 and 2 to 5, while all pixel retention, cleanup and existing failure metrics were unchanged. This exposed insufficient selectivity. A mandatory warning would send ordinary redraws into manual review, undermining casual-user simplicity, so the agents rejected that behavior before committing.

The final implementation shows **Raw body differences** only inside existing Details disclosures. QA status, clean automatic saving, G3 thresholds, retry consent and generation behavior remain unchanged. It is neither an automatic extra-hand detector nor semantic grip certification. The observation aids inspection and future calibration; it does not repair generated art or replace Studio's animation source. No arbitrary wrist radius or new global rejection threshold was introduced.

Shared implementation is in `app/src/lib/image/chroma.ts`, `app/src/lib/items/items.ts`, `app/src/lib/items/qa-summary.ts`, the QA manifest types and existing Studio Details disclosures. It applies to held chroma routes through the shared extractor, rather than only the Motion Lab's failed frame. No new UI kit or backend was introduced.
