## New findings

**Calibration was reusable within an edited fixture but was not retained when switching bodies or reloading.** Explicit saved profiles now restore only the exact body artwork and view. A source document's same-ID imported clip also previously lost priority to the bundled clip when changing the body/view; selection now preserves the imported source. Separate semantic action metadata keeps a control ID such as `kaykit-attack` from becoming the provider's action description. Save/import preserves that metadata, and body/equipment calls share its resolution.

**Sparse samples understate contact uncertainty.** An initial diagnostic based only on the 12 render poses missed all running support intervals. The final diagnostic samples the dense source template and excludes manual edits rather than inventing interpolation. For the current adult south/east walk, fitted speeds are about 24.25/22.56 target px/s with 9.84/9.30 px/s residual RMS. Running yields about 133.58/134.18 px/s but only eight support intervals, about 0.10 weighted support seconds, with residuals 7.87/12.15 px/s. The unequal coverage and high residuals are reasons to reject a claim of solved sole planting. These are requested-ankle proxies, not measured rendered movement. The loop step is explicitly last-to-first sampled joint displacement, not exact cycle closure.

**Rigid attachment preserves shape but does not solve grip and occlusion.** The experiment anchors the extracted standing sword at the requested wrist and rotates by the projected forearm change, using nearest-neighbor pixels. It does not infer a wrist rotation or erase/repaint the body. Corrected front attack sword area stays within 146-152 pixels and east within 167-173, versus the AI route's G4 retention failures at 43%/18% of median. No source pixels clip in those cases. Visual inspection still shows foreground layering through the hand/body, questionable grip/orientation during the strike, perspective mismatch, and raster stepping. The front helmet stays within 151-153 pixels but does not turn correctly with a side-facing head. All four side-helmet controls reject orientation inference because projected ears coincide. The report contains 12 completed rigid comparisons and four explicit ambiguities, all marked unqualified. Stable area is not proof of a good attachment.

**A different source still needs view-specific adaptation.** KayKit's `Death_A` is about 0.8 seconds, so the Quaternius 2.2-second fall schedule cannot be reused. The six KayKit controls use 12 uniform samples and their actual duration. Four initial front/back adult fall cases exceed joint bounds. Reducing only the KayKit fall's root travel from 1 to 0.25 resolves those four; before and after issues are recorded. Final audit: 72 cases, zero joint/reach warnings, maximum bone-length error 8.171241461241152e-14. Silhouettes, hands, visual foot contact, timing appeal and generated equipment remain unqualified. The alternate source is a control, not evidence that changing animation vendors fixes everything.

The free puppet preview exposed wide arms on the initial KayKit walk control. Direct source sampling finds the right upper arm about 49-70 degrees from downward vertical in `Walking_A`, compared with 44-51 degrees in `Walking_C`. A synthetic arms-down reference amplified that lateral motion relative to the target's already angled arms. The final source control aligns neutral arm directions to `Idle_A` at time zero while preserving rest lengths, and uses 0.5 arm influence for walk/run. On adult south, maximum upper-arm angle changes from 89.22 to 53.70 degrees for walk and 95.32 to 59.91 for run; idle changes from 64.21 to 33.42. Both the reference alignment and locomotion weighting changed, so this is a combined adaptation, not an isolated single-factor result. The control remains stylized and unqualified for natural rendered motion. All 72 final cases still pass the bone/bounds audit. An animator-approved source and actual renderer qualification remain necessary.

The official source describes the pack as free CC0 animations with separate medium/large rigs and warns that retargeting can look poor on other characters: [KayKit Character Animations](https://kaylousberg.itch.io/kaykit-character-animations). We downloaded Free 1.1, not paid source Blend files. Archive SHA-256: `65882f31f905ad2e953819648a59287cdeab8f623908d5ef701971d3758be20f`. The included `License.txt`, three sampled GLB hashes, exact node mapping, assumptions and per-case results are preserved in [the independent-source report](2026-10-28-kaykit-comparison.json). Data are parsed, not executed; no package or runtime dependency was installed.

## Use and reproduce

Run normal `npm run dev` from `app/`, then open `/motion-lab.html`. Change reference joints/camera and choose **Save body/view calibration**. Reload or switch bodies and return to the same view to restore it. **Clear saved calibrations** removes saved profiles while leaving the current document editable. Save a motion document to retain timing and pose edits. The **KayKit control** selector loads any of six independent source documents; switching body/view keeps that source. Importing another document still uses the existing validated JSON flow.

From the repo root, with Node 24.22.1:

```text
node spikes/api/mocap/catalog-motion-presets.mts
node spikes/api/mocap/evaluate-motion-equipment.mts
node spikes/api/mocap/compare-kaykit.mts
node spikes/api/mocap/package-motion-review.mts
```

The KayKit bake defaults to the ignored extracted archive under `spikes/api/out/motion-lab-2026-10-28/kaykit-free-1.1/KayKit_Character_Animations_1.1/`; `KAYKIT_PACK` can select another local extraction. It writes the six versioned control documents and license. The original GLB reader, pure converter and PNG/equipment helpers are reused. Raw evidence remains `evidence.json`; frozen candidates and experiments are in the updated `motion-review.zip`, including the new catalog, rigid report and KayKit control documents. [Artifact checksums and experiment summary](2026-10-28-motion-followup-results.json) identify this follow-up separately from the original campaign.

## Verification and disposition

Type checking passes with zero errors/warnings. The full unit suite has 1,023 passing tests and one existing skip. Six relevant browser tests pass, including actual body/view calibration restoration after reload, import, and independent-source switching. The calibration flow passed ten repeats with eight workers and the three Motion Lab flows passed CI settings with one worker. Final rerun details are recorded in the companion result record. Production build and dist guard pass; these dev-only fixtures and UI are absent from production output. Full production E2E and remote CI were not run for the isolated tool.

Initial sandboxed Vitest/Chrome runs failed on Windows cache rename/browser-launch permissions, before application checks could execute. Native approved runs passed. The first new calibration browser assertion compared a saved east-view profile against the body's default south view; the test now explicitly returns to east and retains the original coordinate assertion. No assertion or quality threshold was relaxed.

The implemented workflow is ready for inspection and further authored qualification. **A guaranteed professional six-action equipped library for arbitrary humanoids is not delivered.** The exact unresolved requirements are weapon/hand orientation and occlusion, rendered sole contacts, author-approved visual acceptance, and independent native directions/artwork. Prepared directional attachment art or an authored 2D/3D rig is required for stronger deterministic guarantees; automatically segmenting a single PNG or adding a 3D editor would be a separate product workflow. The branch does not silently change the product to that workflow or label the failed prototypes successful. No additional blind rerolls are recommended from this evidence.
