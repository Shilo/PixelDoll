# Hosting an opt-in owner sync server

Checked 2026-11-23. Prices are USD unless marked EUR, excluding tax. "Unverified" means the figure came from memory or a secondary source, not the official page on that date.

Scope: an opt-in, explicitly temporary third sync target next to Google Drive and Dropbox, on the owner's account, that also supports shared team libraries with near real-time updates. The remote layout stays the current dumb file store (`packs/`, `objects/`, `revs/`, `devices/`, list/get/put/delete), see [cloud-save.md](../../../architecture/cloud-save.md) and [storage-sync README](../../2026-11-22-storage-sync/README.md).

Policy note: AGENTS.md and PLAN.md D31 allow only the stateless OAuth endpoint. Any option here stores user artwork on the owner's server, so it needs the owner's explicit amendment of that rule first.

## 3. Cost model

Assumptions per opted-in user per month:

- 30 MB stored; 20 active days x 8 h = 160 h online.
- 50 edits/day x 20 = 1,000 edits, ~15 KB each (15 MB up). Bundled: one PUT per edit (revision plus item object in one file, head pointer in D1/SQLite). Naive: three PUTs per edit (object, revision, device file).
- Another device or teammate downloads each edit: ~2 GETs per edit = 2,000 GETs, 15 MB.
- One full restore: 30 MB in ~150 GETs (scaled from the 370-request, 99 MB benchmark).
- Egress total ~60 MB. Startup lists ~60.
- Real-time: a WebSocket per open session (~100 connects/month) replaces 60 s polling (which would be 9,600 requests per user). On Cloudflare each edit sends one notify to the library's Durable Object, which wakes ~50 ms and hibernates; idle hibernation is not billed. Polling would instead keep a non-hibernating object alive or add 96 M Worker requests at 10,000 users (~$29), so WebSockets win.
- Supabase: peak concurrent connections 30% of users; ~3 Realtime messages per edit (send plus deliveries, billing basis not confirmed by the docs).
- EUR to USD at about 1.16 (assumed).

Per-user volumes (bundled): R2 class A 1,060, class B 2,150, Worker requests 3,310, DO requests 1,150 (100 connects + 1,000/20 incoming + 1,000 notify RPCs), DO ~7 GB-s.

Notes:

- On Cloudflare, class A writes dominate. Storing the small JSON (revisions, item objects, device heads) in D1 or Durable Object SQLite (rows written $1/M after 50 M included) and only packs in R2 cuts the 10,000-user bill to roughly $25-45, depending on how much JSON is retained (DO SQLite storage $0.20/GB-mo, D1 $0.75/GB-mo).
- Hetzner Object Storage bills small objects as 64 KB, so keep small JSON in SQLite on the VPS and only packs in the bucket.
- Growth: storage grows with revisions (~15 MB/user/month before retention). Storage is cheap everywhere except Fly volumes; requests and egress drive cost.

## 6. Lock-in and exit

| Option              | S3-compatible                           | Export all data                   | Clean shutdown                                                                               |
| ------------------- | --------------------------------------- | --------------------------------- | -------------------------------------------------------------------------------------------- |
| Cloudflare R2       | Yes (S3 API)                            | rclone/S3 tools; D1 export to SQL | Easy: put the Worker in read-only mode, let clients migrate to Drive/Dropbox, delete buckets |
| Supabase            | Storage has an S3 protocol (unverified) | pg_dump plus storage copy         | Easy; pause/delete project                                                                   |
| Firebase            | GCS (S3 interop via HMAC, unverified)   | gsutil/gcloud; Firestore export   | Easy; but disable billing to be sure nothing runs                                            |
| VPS + Hetzner/DO/B2 | Yes                                     | Files are already plain           | Easiest; you own every byte                                                                  |
| Convex              | No                                      | Snapshot export (unverified)      | Moderate; data model is proprietary                                                          |

Because the client stores the full library locally and already speaks Drive and Dropbox, any shutdown can be "announce, go read-only, auto-migrate to the user's own cloud or offer a ZIP export, then delete." That keeps the "temporary and removable" promise honest regardless of host.

## Recommendation

1. **Best overall: Cloudflare Workers + R2 + Durable Objects (hibernating WebSockets) + D1.** $0 at 100 users on a Free plan that fails instead of billing, ~$6 at 1,000, ~$65 at 10,000 (less with JSON in SQLite); edge latency, real-time rooms per library, S3 exit, same account as the existing token Worker. Weakest point: 2025-2026 outage record and no hard cap on R2/DO beyond the Workers limit.
2. **Cheapest at scale: Hetzner VPS + Object Storage.** Fixed ~$8 / $21 / $31 regardless of request counts, but single region, no SLA and the owner must patch, back up and monitor it.
3. **Most reliable on paper: Firebase (multi-region GCS + Firestore listeners).** Mature durability and SLAs, but Blaze has no hard spending cap and egress makes it ~$140 at 10,000 users.
4. **Simplest to build: Supabase Pro.** $25 flat up to ~1,000+ users with auth, realtime and a default spend cap, but single region, no SLA and Realtime message pricing grows with teams (~$148 at 10,000).
