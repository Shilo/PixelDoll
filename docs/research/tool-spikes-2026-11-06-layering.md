# Research spike on deterministic wardrobe assembly

2026-11-06. This is the layering group for the [external tools review](tool-review-brief-2026-10-28.md), using the [October 27 review](paperdoll-repos-review-2026-10-27.md) as the baseline. The comparison covers authoring, fit, occlusion, dye, and handoff to a game engine.

**Evidence.** Source-verified means read at the revision linked below. Publisher-reported means the developer documented or demonstrated a feature, with no independent runtime verification. Measured means an independent read-only Node probe on PixelDoll inputs or a reproduction with its actual composition functions. Proposed behavior and estimates are inferences. Public GitHub source snapshots were downloaded and inspected as data. The commercial Unity package, unsigned Fantasy Character Generator executable, and game client data were outside the executed checks. The WebGL demo was inspected through its delivered HTML and loader configuration and tried in the Codex browser by the coordinating agent. No packages were purchased, no external code was incorporated, and this spike made zero PixelLab requests.

## Paper Doll Studio

**Source-verified.** This is a portrait and visual-novel wardrobe compiler with a local browser UI and a Python/FastAPI process. Its artist path reads a layered PSD and categorizes layers by names. Its flat PNG path uses an anime SemanticSAM taxonomy to propose layers from visible pixels. A clothed flat input leaves gaps in the underlying body where clothing covered it. Both paths produce the same wardrobe configuration. The inpaint worker uses a fresh composite of the base layers, one garment at a time. It conditions SD 1.5 at 512 × 512 using a mask, with optional IP-Adapter style or ControlNet geometry. An output can be split by semantic category, refined as a single region, or passed to cleanup. This is an independent example of treating the untouched base and the garment reference as separate inputs. [Paper Doll Studio source and README at ed94d5f](https://github.com/KhurrumAli1997/paper-doll-studio/tree/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc) · [Inpaint worker](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/scripts/inpaint/worker.py#L299)

**Source-verified.** It separates manual placement and bake from an opt-in warp. The warp requires user-confirmed category anchors, filters to the stable subset, then runs affine or a blended piecewise transform. It scores silhouette IoU, precision, recall and mean edge distance against an allowed region. A missing reference region warns and skips scoring. The compiler writes source, cleaned, fitted and final previews and a fit report. Allowed-region clipping is opt-in. For upper-body garments it can split sleeves from the torso by an arm-region mask and assign separate depths. The current contract records a compatible body archetype and pose, and the default compatibility target is a standing pose. [Compiler](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/compiler.py#L129) · [Fit pipeline](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/fit_pipeline.py#L68) · [Fit scoring](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/fit_validation.py#L140) · [Sleeve split](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/split_slots.py#L6)

**Source-verified.** The cleanup workbench distinguishes a transparent PNG, white background, and clothed guide. It can show the stencil as an overlay, clip optionally, measure coverage outside the stencil, preserve small outside details, and erase or restore with undo. The deterministic tailor constructs an image from silhouette geometry and fills, outlines and shadows. The reference pack exports silhouette, outline, Canny, depth and pose as separate channels. Those channels can be useful in diagnosis even when the destination API accepts fewer inputs. Its ZIP packages a configuration and assets rather than a runtime animation manifest. Missing asset fetches can log and continue, which can produce a ZIP with an unresolved reference. Preview dyes use CSS filters on hair and eyes. [Cleanup](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/js/cleanup.js#L236) · [Pattern construction](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/pattern_constructor.py#L875) · [Reference pack](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/compiler/reference_pack.py#L199) · [Export](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/js/export.js#L165) · [Dye preview](https://github.com/KhurrumAli1997/paper-doll-studio/blob/ed94d5fe4b1750b34ce73d2ffde1abbd1ef766cc/js/render.js#L90)

**Challenge.** Borrow the diagnostic stages and the distinction between a reference region and an allowed edit region. PixelDoll already has an exact post-extraction stencil for submitted inpaint masks and pose-sensitive checks for several slots. Whole-body silhouette IoU has weak semantics for a garment that deliberately protrudes. Confidence thresholds tuned for the portrait app, arbitrary scale or affine resampling, CSS hue rotation, segmentation of hidden anatomy and full-image redraws are poor fits for frame-aligned pixel layers. A free editor that removes stray alpha or restores source pixels could help people fix the last few bad pixels, provided it works inside the existing Frame Editor scope and presents the original immutable cell alongside the candidate. PixelDoll's review already exposes a QA summary, paid repair scope, and a free palette repair. The missing step is a spatial explanation for *where* a frame diverges. ## Willyxz Paper Doll System for Unity and Netlify DemoScene

**Publisher-reported.** The Unity plugin assembles pre-authored Farmer Base sheets. Its workflow expects specific Resources folders, a controller on an empty object, an inspector setup action, and optional weapon prefab integration. Runtime equipment and palette swaps, weapon animation, separate shield depth, and the TopDown Engine adapter are the main advantages. The setup guide calls for gamma color space. The listing advertises broad compatibility, while the developer states that the older Mana Seed Character Base uses an incompatible sheet and color contract. The plugin does not create new sheets from a prompt or retarget arbitrary equipment between bodies. [Willyxz listing and setup](https://willyxz.itch.io/paper-doll-for-farmer-base) · [Developer compatibility clarification](https://itch.io/post/16020340) · [Farmer Sprite System publisher announcement](https://itch.io/devlog/1016714/unity-plugin-now-available.amp)

**Verified linkage and publisher-reported limitations.** The itch listing links the supplied Netlify URL as `DemoScene`. The Netlify page returned HTTP 200 and identified itself as Unity player `TestPaperDoll`, version `1.0`, with a 960 × 600 canvas and `Build/webgl.*` loader, data, framework and Wasm assets. The delivered page exposes a compiled player. The Unity source and manual were not publicly available in this inspection. A shield update fixed a weapon layer playing one frame out of sync and an adapter issue where an outside script interrupted an attack. Another update says material-property-block recolors do not appear in prefab previews. These examples support checking cadence, outfit state and the actual rendered Unity prefab as part of export verification. [Willyxz WebGL DemoScene](https://glowing-semolina-477fd8.netlify.app/) · [Shield and timing update](https://willyxz.itch.io/paper-doll-for-farmer-base/devlog/1059960/shield-support-added) · [Prefab preview update](https://willyxz.itch.io/paper-doll-for-farmer-base/devlog/1412550/paperdoll-system-update-improved-prefab-preview)

**Observed in the Codex browser.** Randomize visibly changed the character and outfit. The demo exposed melee, tool, bow, fishing, bug-net and scythe categories with equipment and ramp arrows. Selecting Bow, using a weapon ramp arrow, moving east with D, and attacking with Space produced a visible east-facing bow animation with the outfit still worn. The run did not isolate the color change from weapon selection or measure frame-by-frame phase. It verifies a functional assembly preview with a fast route from equipment selection to an in-motion check. [Willyxz WebGL DemoScene](https://glowing-semolina-477fd8.netlify.app/)

**Challenge.** The useful unit is one authored frame contract shared by the base and all equipment, including the sampling clock and the depth state. PixelDoll already exports a Unity prefab importer, pivot-aligned SpriteRenderers and a single sampled clip state. The comparable gaps are proving Unity parity on actual imported assets and exposing the runtime anchor tracks. A second independent weapon animator or forcing users to change project color space would introduce more coupling. The shield and long-hair updates also show that a stable grid alone cannot define occlusion. [Unity importer and runtime](../../app/src/lib/export/unity.ts#L98) · [Willyxz long-hair update](https://willyxz.itch.io/paper-doll-for-farmer-base/devlog/1112589/paper-doll-system-version-120-long-hair-compatibility)

## Fantasy Character Generator

**Publisher-reported.** ToshaAngel assembles offline pre-rendered Blender layers for four authored body variants. The published library has 76 items, 40 clips and eight directions. The normal grid is 15 frames at 128 px per cell and 10 fps. The studio offers presets, up to three color zones per item and up to 200 random NPCs from one preset. Each weapon can be drawn in its stance and in shared reactions, or put away on the hip or back in other clips. A drawn sword can leave the empty scabbard visible. The author lists cloak, travel pack and quiver but the exact simultaneous wear and clipping rules could not be verified. Export can produce single frames, direction strips, animation sheets, RPG Maker layouts or selected item/body/shadow layers, with JSON for dimensions, direction order, frame rate and feet position. The 30-degree orthographic artwork is rendered at higher resolution, with optional outline and shadow. [Fantasy Character Generator listing](https://toshaangel.itch.io/fantasy-character-generator)

**Challenge.** Here, equipment compatibility comes from authoring every layer for a fixed set of bodies, camera, motions and equipment states. The advantage is predictable cost and coverage at runtime. It does not generalize to arbitrarily generated body shapes. The free demo is a Windows native download and the developer describes its art as testing-only. End-to-end export, measured speed, JSON field names, internal masks and color-zone mechanics are unverified. The product's small menu of named material controls is worth comparing with PixelDoll's inferred exact ramps. For AI-generated art, two materials that use the same RGB cannot be made independently dyeable by an RGB lookup within a single item. A spatial mask or author-assigned index is required, and assuming semantic equivalence from a palette cluster would be misleading. PixelDoll already supports per-item palettes and a local random-outfit action, so batching would serve a distinct NPC production task and is secondary to reliable item coverage. [PixelDoll material derivation](../../app/src/lib/dress/dress.ts#L59) · [Random outfits](../../app/src/lib/dress/dress.ts#L162) · [Coverage gaps](../../app/src/lib/dress/dress.ts#L195)

**Proposed.** Treat carried and stowed as authored artwork states tied to the *same design*. Select the state from the current move and equipment policy. The engine should never use an arbitrary translation of a held weapon over the hip. Drawing, stowing and scabbards need different occlusion, coverage and anchors. A separate garment slot for a pack or quiver would address a genuine exclusivity problem first. The current slot map allows one item in `back`, and the held prompt explicitly excludes scabbards. Splitting the slot requires testing cape and backpack depth together, including when the pack should occlude the cloth. [PixelDoll slots and held prompt](../../app/src/lib/items/items.ts#L124) · [Equip contract](../../app/src/lib/compose/compose.ts#L24)

## Ultima Online paperdoll drawer

**Source-verified.** The PHP library is a static portrait compositor over client resources. It reads the gump index and run-length art, resolves wearable and race/gender art using tile data and ID offsets, and draws a body then the submitted item entries in order. Its domain taxonomy distinguishes cloak and backpack and inner and outer legs. The drawer itself does not sort by those enum values or implement item-specific exceptions. Its hue code indexes RGB555 channels through a 32-entry table. The intended partial hue only remaps grays, but the reader masks away the flag before the painter tests it. It also skips black runs when drawing, which would remove intentional opaque black outlines from PixelDoll. These findings confirm the relevant October 27 source conclusions. [Layer taxonomy](https://github.com/ppardalj/ultima-paperdoll-drawer-php/blob/274b491e90d4bfa02156b54fdcc3afba7bf93192/src/Domain/Layer.php) · [Drawer](https://github.com/ppardalj/ultima-paperdoll-drawer-php/blob/274b491e90d4bfa02156b54fdcc3afba7bf93192/src/PaperdollDrawer/PaperdollDrawer.php#L57) · [Hue reader and lost flag](https://github.com/ppardalj/ultima-paperdoll-drawer-php/blob/274b491e90d4bfa02156b54fdcc3afba7bf93192/src/Muls/HueReader.php#L28) · [Partial-hue predicate](https://github.com/ppardalj/ultima-paperdoll-drawer-php/blob/274b491e90d4bfa02156b54fdcc3afba7bf93192/src/Muls/GumpArtReader.php#L48)

**Challenge.** Split exclusivity by clothing intent and carry explicit item-specific depth exceptions in PixelDoll's own contract. Preserve its exact alpha and RGB semantics. The lookup-texture idea is an adaptation of palette indexing, and not an export implemented by the PHP library. This spike only uses the GPL-3.0-or-later repository as conceptual evidence. [Ultima package metadata](https://github.com/ppardalj/ultima-paperdoll-drawer-php/blob/274b491e90d4bfa02156b54fdcc3afba7bf93192/composer.json)

## Offline results

**Measured.** An independent Node probe used the app's pure PNG codec, fixture loader, compose functions and color math. For each opaque item pixel in a registered frame it asked whether the corresponding bare-body pixel was opaque, and aggregated ratios across nonempty cells. The retained percent is what would survive a hard whole-body clip. It does not measure artistic quality or replace the external app's category-specific mask.

| Input | Cells | Retained min / mean / max |
|---|---:|---:|
| Demo helmet | 38 | 35.0% / 53.3% / 72.7% |
| Demo hair | 38 | 33.0% / 46.4% / 61.9% |
| Demo cape | 38 | 7.1% / 24.8% / 75.7% |
| Demo sword | 38 | 0.0% / 7.4% / 46.5% |
| Demo vest | 38 | 72.2% / 89.8% / 100.0% |
| Round 9 `x28` EA2 attack cloak, south and east | 16 | 6.5% / 12.3% / 20.1% |
| Round 8 `x26` green-key standing cloak | 4 | 17.3% / 29.6% / 63.0% |

The demo comparison uses the 64 px rig cell, including mirrored west and clipping to that cell. The `x28` probe pairs the saved `ea_cloak_v3_attack_l` layers with the matching `v3_attack_l` body frames after dropping the echoed input at frame zero. The `x26` probe derives a cloak candidate from `X3/state_cloak` with `chromaLayer`, using the corresponding `import_skin` standing images. Preserve cape swing and weapons extending beyond the character by conditioning and evaluating around the attachment, with a separate permission stencil when the allowed editing area is known. PixelDoll already distinguishes this case. `dropOffBody` retains the largest component and only removes detached components for body-hugging, non-wrap slots. [Existing component rule](../../app/src/lib/items/items.ts#L635)

**Measured.** Swapping the fixture's older z overrides for current defaults changed 9 pixels over east walk and 9 over west walk, and 3 over south cross-punch, in the cape, hair, sword and vest outfit. North did not change. This confirms current defaults already address some cape/hair and cape/held interactions. It is not a counterexample to the old wide-robe issue because the fixture has a fitted vest. For a stronger reproduction, applying an east head override of 70 and an all-directions override of 132 to the actual fixture makes both helmet and wizard hat resolve to 70 in east and 132 in mirrored west. The item inspector presents the operation on one item, but saves the change on the slot. Direction-specific precedence also means a later all-directions click leaves east unchanged. [Current slot defaults](../../app/src/lib/items/items.ts#L162) · [Depth controls](../../app/src/studio/ItemPane.svelte#L218) · [Slot write](../../app/src/studio/state.svelte.ts#L608) · [Resolver](../../app/src/lib/compose/compose.ts#L152)

**Measured with synthetic hide rules on real fixture items.** In the helmet + cape + hair outfit, setting helmet to hide `back` and cape to hide `hair` removed both from the draw list. Clearing the hidden cape's hide list restored both hair layers under the helmet while the cape remained hidden. The existing rule deliberately aggregates hides from all equipped items and is mirrored by the engine exports. A visibility-based replacement must define precedence for mutual hides and use the same result for clipping and body cuts. Adding backpack/outer-leg slot combinations before deciding this would make the odd behavior easier to trigger. PixelDoll currently rejects exporting two populated slots that both clip the same target, and warns when two worn body cuts cannot be represented by the engine's one baked body variant. [Current hidden/tuck policy](../../app/src/lib/compose/compose.ts#L29) · [Export limits](../../app/src/lib/export/export.ts#L20)

**Measured.** The demo's 13 stored layer sheets contain at most 45 visible RGB values per sheet and no partial-alpha pixels. Original sheets total 37,269 bytes, matched by re-encoding with PixelDoll's filter-0 RGBA8 encoder. An independent filter-0 grayscale PNG encoder plus one tiny RGBA8 lookup per sheet measured 24,881 bytes combined, 33.2% smaller. Palette index 0 reserved transparency and reconstructed every visible source RGB byte-exactly. Packing that index into RGBA8 instead increased the total to 42,717 bytes with lookup textures. The probe uses per-sheet lookup order and checks visible pixels, so it does not measure production ZIP size or engine memory. Runtime adoption would require stable per-item material entries across moves, protected outline/unmapped colors, an escape for sheets with over 255 visible values or soft alpha, and point-sampled index data with correct linear/gamma handling. For the existing engines, the lower-effort path to arbitrary runtime dye is to generate new ramps over existing exact RGB material tables. Phaser already accepts stored variant selections and swaps exact owner-local RGB, with similar support in other runtimes. [Index and swap primitives](../../app/src/lib/dress/palette.ts#L111) · [Variant export](../../app/src/lib/export/generic.ts#L121) · [Phaser palette path](../../app/src/lib/export/phaser.ts#L95)

**Measured.** For the largest inferred ramp per demo item on Walk, applying the same azure to a cape, helmet and vest changed mean OKLab lightness from 0.327 / 0.600 / 0.518 to 0.517 / 0.517 / 0.517. An independent prototype reused the hue of the pick and reduced chroma as needed for gamut while keeping the source L at each step. Its result was 0.327 / 0.600 / 0.518 to three decimals. This supports a material-preserving rule for a shared outfit dye. Per-material color picks should still aim at the selected swatch and retain internal contrast. It does not support a global recolor switch by itself. [Current variant rule](../../app/src/lib/dress/palette.ts#L94)

## Ranked changes and acceptance criteria

| Rank | Opportunity | Effort and paid validation | Acceptance criterion |
|---|---|---|---|
| 1 | Show candidate alpha, source pose, and changed pixels at the specific flagged cell. Fit the free overlay and small correction tools into the existing Frame Editor design. | Small for a read-only diagnostic, medium for a reversible editor. No paid generations needed. | Selecting an item issue opens the exact cell and direction and lets the user distinguish a displaced edge, missing pixels, and color drift. Export sees the accepted edit, with frozen body and paid source history preserved. |
| 2 | Give layer-order controls item-level meaning across preview and engine exports. Decide whether an explicit west correction can differ from the mirrored source, how all-directions supersedes prior per-direction user overrides, and how reset preserves defaults. | Medium, because exported manifests and all consumers must agree. No paid generations. | Two hats in one slot retain different orders. Reset affects only the selected item. The composed preview and at least one live engine runtime agree on forward/backward, per-direction and all-direction cases. |
| 3 | Expose runtime anchor tracks from the existing rig and use them for attachments and effects. | Small per engine plus shared spec/tests. No paid generations. | Hand, head and feet coordinates follow the sampled animation cell. Mirrored views flip spatial x around the rig pixel edge, with an explicit policy for anatomical left/right. Missing estimated joints are represented as unavailable. [Existing track schema](../../app/src/lib/rig/rig.ts#L38) · [Track generation](../../app/src/lib/rig/freeze.ts#L91) |
| 4 | Keep the base body version as the exact reuse contract. Let saved shared designs reuse identical geometry, and price refit per distinct body through the existing library. | Medium to large. Offline exact-copy tests first. Paid validation for widened refit support. | Same-body assets copy without spending and retain the full move grid. Different bodies show a priced compatibility choice and retain the original design. The existing paid qualification is deliberately narrow. [Exact compatibility](../../app/src/lib/equipment/compatibility.ts#L21) · [Paid qualification](../../app/src/lib/equipment/generate.ts#L33) |
| 5 | Separate cape, pack and quiver only with an explicit overlap policy, then consider stowed equipment as a separate authored state. | Medium for slot rules, large for carried/stowed states. Existing assets can test composition for free. New generated clip coverage needs paid validation. | One outfit can wear a cloak and pack without double clipping. A carried weapon uses the right hand or its matching stowed artwork on every intended move, with coherent scabbard and grip occlusion. |
| 6 | Support arbitrary runtime dye on the existing RGB material tables before considering indexed textures or spatial zones. | Medium per engine. No paid generations for shader/CPU benchmarks. | New colors preserve alpha and protected colors. A shared hue can retain material lightness when called for by the outfit task. An indexed sidecar earns inclusion only after size and actual engine memory gains outweigh implementation and integration costs. |

No direct adoption is justified for the portrait app's local diffusion or affine fitting, the Unity plugin's asset names or second clock, the commercial generator's preset art or closed catalog, or the Ultima RGB555 and black-transparency scheme. A useful cross-tool boundary is to treat frame ownership, appearance, and depth as separate data, and to show where a result broke that contract before charging for another draw.
