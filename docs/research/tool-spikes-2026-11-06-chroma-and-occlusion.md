# Research spike on chroma extraction and pixel ownership

This spike examines an independent masked sheet-dressing workflow and checks its implications against PixelDoll. **Verified** identifies behavior inspected locally or reproduced with current code. **Reported** identifies practitioner observations. **Proposed** identifies follow-up work. The tests were offline.

## What the workflow teaches

**Reported.** Start with registered, finished poses. Map identified skin to a five-shade cyan ramp before dressing, protect areas outside the garment’s intended reach, and instruct the editor to reserve cyan for the mannequin. Remove key-colored pixels and pixels unchanged from the keyed input, then composite the extracted clothing over the original poses. The temporary color preserves enough shading to cue the model while giving the extractor a recognizable hue family. Manual review still resolves repainted skin, hair edges, and overlaps between fringe, eyes, and eyebrows.

**Verified.** In one bounded dressing example, every protected opaque input pixel was preserved, keying preserved input alpha, and all extracted garment pixels stayed inside the allowed region. This demonstrates feasibility with known alignment and a valid mask. It provides one case and cannot establish a success rate across materials, views, or motions. A comparison of aligned color variants found both exact preservation and small alpha differences. A palette-only operation should preserve alpha and placement exactly, which makes those properties worth checking independently.

**Reported.** Separately editable hair, skin, eyes, eyebrows, and mouth make color variants and expression changes possible without redrawing the head. A fringe can legitimately overlap the forehead while an eye or brow should remain visible for a given design. Long hair may need both front and back pixels. This is a layer ownership problem alongside the color selection problem.

## Where PixelDoll already matches the workflow

- PixelDoll keys the entire opaque mannequin through a luminance ramp and preserves its alpha. It selects from green, magenta, blue, and azure using prompt color words. It keys out a hue family, suppresses contaminated edges, and removes small components. A skin-only key would require a reliable skin region in each frozen pose. Global removal of cyan would discard valid turquoise equipment when the key collides with an item color. [Chroma key selection and extraction](../../app/src/lib/image/chroma.ts)
- Frozen-frame inpainting supplies a hard mask and a protected same-direction reference. Extraction uses the submitted mask and clips both the equipment layer and any body cut to that permission boundary. A mask built from a trustworthy region can protect facial features or hands even if the provider paints across them. A narrow mask without adequate shape evidence can also cut off a sleeve, hem, or shoulder plate. [Grid request and retained mask handling](../../app/src/lib/items/run.ts) · [Stencil enforcement](../../app/src/lib/items/items.ts)
- Hair already has separate front and back output layers. The default split uses overlap with the base alpha, and helmet tucking uses the cover’s lowest opaque row per column. Those rules serve typical overlap and brim cases. They cannot distinguish an eye from a forehead pixel, place rear hair behind a body pixel that the candidate painted over, or recover pixels absent from the generated image. [Front and back split](../../app/src/lib/compose/split.ts) · [Tuck rules](../../app/src/lib/compose/compose.ts)
- Recoloring applies exact palette indices and can keep colors owned by different items independent. Within a layer, two regions sharing an RGB value still need spatial ownership if the user wants to edit only one of them. A global skin-tone deletion would risk removing leather, metal highlights, and intentionally skin-colored shading. [Material ownership and recoloring](../../app/src/lib/dress/dress.ts) · [Palette indexing](../../app/src/lib/dress/palette.ts)

## Reproduced failure and a bounded remedy

**Verified offline.** On a synthetic 32 px cell, paint a 16 × 23 opaque base rectangle starting at (8, 4), convert it to green, and add a 14 × 9 red garment at (9, 14). Add a separate 4 × 3 off-key skin-colored patch at (13, 11). The production `extractCell` returns 138 candidate pixels, including all 12 repainted skin pixels. Its reported key preservation is 1.0 and G2 passes because `keyKept` excludes the pixels already classified as item foreground. Giving `extractCell` a trusted stencil starting at row 14 retains all 126 garment pixels and removes all 12 forbidden pixels. This isolates G2’s limit. The probe does not score the entire item QA pipeline.

**Verified offline.** For a synthetic three-pixel hair layer, both pixels over opaque body alpha go to the foreground and the pixel outside the silhouette goes to the background. An author cannot use that split alone to put one overlapping pixel behind the face and leave another in front. The renderer would need explicit pixel ownership for that distinction.

## Ranked opportunities

1. **Show protected pixels and extraction disagreements during review.** In the existing review flow, compare the frozen body, extracted layer, and dressed preview for one flagged pose. Where a submitted mask exists, identify the protected region explicitly. Distinguish masked-out changes from ambiguous changes inside the editable region. Keep these checks diagnostic until they distinguish real overlap from leaked mannequin pixels on a varied fixture set. **Effort:** small to medium. **Paid calls:** none to build or exercise on retained output. 2. **Prototype precise local edits in the frame repair workflow.** Use an explicit per-cell keep/erase or front/back mask with the existing hard-stencil and split conventions. An edited candidate can recover protected eyes or separate rear hair without changing the stored body. Test hair over eyes, deliberate eye covers, tied hair, mirrored views, and export parity before extending the format. **Effort:** medium. **Paid calls:** none for local edits. 3. **Evaluate restricted skin keying and quantization offline first.** Compare the current luminance ramp and a five-shade ramp on non-private fixtures across skin tones, dark outlines, leather, warm metal highlights, and blue-green equipment. Score retained clothing, off-key bleed, region recall, and exact alpha preservation. Qualify the skin-only route only where region masks have reliable coverage across frames. Leave broad requests and generation defaults unchanged pending provider evidence. **Effort:** medium. **Paid calls:** none for local preprocessing and extraction, later matched provider samples for a quality claim.
