# PixelDoll cost calculator model

November 22, 2026 · PixelDoll revision `49ecdb3e1` · Offline research. A **generation** is a PixelLab billing unit. Price a concrete set of requests per character, then sum the project. Show first-pass estimates, optional additional attempts, and unknown prices together. Existing artwork can seed either a **rebuild budget** or a **remaining work budget**. Default to rebuild for comparing project sizes and label the scope explicitly.

## Subscription generation prices

**M** means a measured price or retained usage receipt at the stated inputs. **D** means a documented rate. **P** means a provisional estimate, inferred boundary, or missing rate. These are the rules PixelDoll applies today. Source paths below start at `app/src/` unless labeled otherwise. Endpoint paths omit `/v2`.

### Character and rig

Let `A` be the drawing area, `D` the count of independently drawn project facings, and `J = 0.1` per paid skeleton measurement. Body draw size and project frame size are separate. Validate model bounds and the 4 px body-size step before applying `costBody`. The creator draws and registers all eight originals, even when the project uses a subset or mirrors some of them.

### Body Moves

For each selected independent facing, `F = moveFrames(manifest,spec)` is the number of requested body output cells. Playback repeats and timing edits do not add cells. Use `moveFrameCounts` and the actual model to validate `F` (Skeleton V3 3–15, PixMiniMax 4–40 in steps of four, Text V3 even 4–16 subject to app area limit). `P(F) = 2` through 3, 3 through 12, then 4 for one Skeleton V3 call. Three/eight/15 are documented, up through 12 includes measured cases, and 13–14 use a provisional upper rung. Native prices are per draw, not per returned playback frame.

### Equipment, fit and repair

`C = max(w,h)` for the submitted item cell. `editFrameCap(C)` is 16 through 64 px, 9 through 80 px, otherwise 4. `E(C) = editGens(cell)` is 10 through 128 px, 15 through 170 px, otherwise 25 through 256 px (**D**, **M** at sampled tiers). For held Skeleton V3 items, add `p = max(0,min(16,floor((256-max(w,h))/2)))` pixels on **each** side, preserving the pivot. Anchored items use the unpadded rig cell. Repair uses the saved layer cell if present.

### States

A generated State is one new still body cell per available independent facing, sourced from Standing or a selected playback frame's art. It has its own route and cost, with no automatic joint fitting, animation, or equipment refit on save. Imported or locally captured State art adds zero for the capture. Source: `studio/stateGenerationSource.ts:26–57`, `studio/stateGeneration.ts:301–347,751–807`.

- **Subscription allocation.** `usedUnits * paidMonthlyPrice / monthlyAllowance`. `units / monthlyAllowance` gives allowance equivalents, with no delivery-date implication. An existing user within available allowance can have zero incremental cash spend. A new subscription costs the plan invoice, and unused allowance raises the effective cost per unit actually used. Annual users can enter their monthly-equivalent price (annual invoice ÷ 12) and confirmed allowance. The public cards advertise yearly billing and a Tier 3 $100 annual saving. Exact Tier 1/2 annual checkout amounts, discount eligibility and the actual user's invoice were unverified.
- **USD credits.** Sum the endpoint-specific USD costs for the requests expected to be paid from credits, using the same shapes/frame counts and dated catalog entries or matching receipts. There is no universal USD-per-generation rate. Example catalog ratios: 64 px V3 scratch draw $0.041/2 = $0.0205 per gen, 8-frame Skeleton V3 $0.0513/3 = $0.0171, edit-animation through 128 px $0.08/10 = $0.008. The catalog labels USD estimates variable with processing time. Use exact catalog matches with provenance, show unknown prices for unmatched inputs (including registration-only USD when unavailable), and leave taxes and invoice fees outside the estimate. [Public API catalog](https://www.pixellab.ai/pixellab-api)
- **Balances.** `Balance` contains `credits.{type,usd}` and `subscription.{type,status,plan,generations,total}`. Read the existing `app.balance` snapshot and timestamp, with disconnected, stale and error states. `accountTier` parses numeric active/enterprise plans, recognizes trial/none/expired as local tier 0, and returns unknown for missing/unrecognized accounts. There is no invoice price, renewal date, usage forecast, rollover balance, credit expiry, billing preference, or per-request price matrix in the response. `PLAN_JOB_LIMITS` is local concurrency policy. Use `requestTier`/`workflowTier`: animation edit, image edit and transfer need Tier 1 locally; inpaint requires Tier 2 above 256 px on either side. An unknown tier or unmapped State route leaves provider access uncertain. Sources: `lib/pixellab/routes.ts:320–329`, `lib/app.svelte.ts:122–148`, `lib/pixellab/plans.ts:5–82`, [plan policy](../../pixellab-plans.md).
- **Mixed funding.** The repo's dated capabilities note reports subscription-first then USD credits. Public evidence reviewed did not establish REST spillover at an individual-request boundary, whether one request can split pools, credit purchase denominations/fees, paid monthly rollover, or USD credit expiry. Show both unit and credit budgets as labeled scenarios and never add both prices to the same operation. Free slower-generation storage is advertised separately. ## Acceptance and price drift

- Show a first-pass interval for known conditional costs and priced routes, with unknown steps listed alongside it. Offer a second scenario with explicit extra attempts by stage (e.g. one redress, three pose rerolls or one selected-facing grid repair). Add those calls and any selected dependent refits once. A uniform 2× is a sensitivity preset only. No finite bound predicts accepted art.
