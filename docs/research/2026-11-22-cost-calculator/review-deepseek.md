## Worked example 3 recomputation

The stated `98.65` is correct. Recomputed from code:

1. Base, 128 px V3 text: `1 + 0.25 + ceil(128*128*8/65536) = 1.25 + 2 = 3.25`. The 0.25 is registration (`app/src/studio/create.ts:306-326`).
2. 4-frame Text V3 Idle, 4 facings: `4 * (ceil(128*128*4/65536) + 4*0.1) = 4 * 1.4 = 5.6` (`app/src/studio/create.ts:2412-2421,2634-2649`).
3. 12-frame PixMiniMax Attack, 4 facings: `N = table[128][12/4 - 1] = 2`, so `4 * (2 + 1.2) = 12.8` (`app/src/studio/create.ts:2395-2421`).
4. Hair on both moves: dress at 128 px, `editFrameCap(128) = 4`, 4 facings fit one call, `editGens(128) = 10`. Poses: Idle `poseBatches(4) = [4]`, `P(4) = 3`, 4 facings = 12; Attack `P(12) = 3`, 4 facings = 12. Total `10 + 24 = 34` (`app/src/lib/items/items.ts:629-670,695-725,740-745`; `app/src/lib/rig/clips.ts:217-234`).
5. Held referenced on Attack at 128 px: `p = min(16, floor((256-128)/2)) = 16`, cell 160. Dress cap `editFrameCap(160) = 4`; reserve one reference, so batches are 3 then 1, two calls at `editGens(160) = 15` = 30. Poses `4 * 3 = 12`. Total `42` (`app/src/lib/items/items.ts:423-436,629-670,726-736`; `app/src/studio/itemRoute.ts:141-158`).
6. Pixen State, 4 facings at 128: `compactSheet` packs 4 into 256 x 256, one batch, fixed 1 gen (`app/src/studio/stateGenerationPlan.ts:117-131,195-210`).
7. Sum: `3.25 + 5.6 + 12.8 + 34 + 42 + 1 = 98.65`.
8. First-pass ceiling: `estimate.maxGens` adds `4 * 0.1 = 0.4`, giving `99.05`.
9. Repair one hair Idle facing: 128 px cell, 4 frames. Without `preferTierOne`, capacity at 512 is 15, one batch; `repairGridLayout` chooses 384 x 256, mean 320, 15 gens, Tier 2. With `preferTierOne`, capacity at 256 is 3, two batches at 10 each, 20 gens (`app/src/lib/items/items.ts:238-321`).

## What a calculator must count that the spec misses

- **Walk and authored actions override the frame count.** `moveFrames` forces 8 for `action: 'walk'`, uses the authored pose table length for known actions, and lets `animation.frameCount` win; only then does it fall back to the form's frames. Use this resolved F, not the entered frame count (`app/src/studio/create.ts:2379-2393`).
- **A new move's frame count is snapped to a valid count when it carries an animation block without an explicit `frameCount`.** `defaultMoveFrameCount` chooses the nearest legal count for the model and canvas, so the priced F can differ from the preferred value; a move without an animation block uses the preferred value as-is (`app/src/studio/moveAnimationOptions.ts:44-61`).
- **The default item route is not always skeleton.** `defaultMethod` returns anchor unless `canPose` holds for every selected clip and direction; `key: 'none'` also forces anchor. Anchor prices use the unpadded rig cell and `planCalls`, not one dress plus pose calls (`app/src/lib/items/run.ts:203-209,229-232`; `app/src/studio/itemRoute.ts:131-138`).
- **Managed State eligibility has extra gates.** It requires the Default move, frame 0, a character ID, no reference and a description of at most 1000 characters. Any failure switches to a local route with a different price (`app/src/studio/stateGeneration.ts:300-328`).
- **State route gates change the price itself.** Native local Pro requires `shortest(cell) >= 32` and `side <= 512`; Pixen rejects `side > 256`; the animation route requires two or more cells per batch. These are not just warnings; they select another endpoint (`app/src/studio/stateGenerationPlan.ts:195-290`).
- **The managed State quote is flat, local routes scale by batch.** One `create-character-state` request is 10, 15 or 25 gens for the whole parent, regardless of facing count. Do not charge it per facing (`app/src/studio/stateGeneration.ts:337-346`).
- **Redraw is not an inpaint repair.** Redraw uses `/edit-images-v2`, whose local minimum tier is 1 at any size. Do not apply the inpaint Tier 2 threshold above 256 px to a redraw (`app/src/lib/pixellab/plans.ts:36-45`; `app/src/lib/items/items.ts:288-306`).
- **Draw and registration must be summed once.** `estimate.gens` and `estimate.maxGens` already include the 0.25 registration, while `apiPlans` shows the draw as `estimate.gens - 0.25` plus a separate 0.25 registration line. A calculator that adds both presentations double-counts 0.25 (`app/src/studio/create.ts:306-326`; `app/src/studio/apiPlans.ts:202-251`).
- **A failed registration can cost another 0.25.** A new registration seed buys a fresh `create-character-v3` import; `setupRegistrationStuck` is the gate. Optional attempts must include it (`app/src/studio/setup.ts:54-67`; `app/src/studio/create.ts:206-207,1397`).
- **Measurement and creation caches are keyed by request hash.** Identical start images, joint checks, completed creations and registrations can be free on replay. First-pass plans charge every occurrence; a remaining-work budget must dedupe by hash before subtracting (`app/src/studio/create.ts:597-607,1319`; `app/src/lib/rig/setup.ts:84-102`).
- **Held padding is per cell and can be zero.** `padOf` is not always 16 px; at a 256 px rig it is 0. Dress canvas and pose prices must use the actual padded cell (`app/src/lib/items/items.ts:429-436`).
- **An item reference must fit the padded cell.** The reference occupies a conditioning slot and is rejected when larger than the padded frame. A calculator should validate that before showing a price (`app/src/lib/items/items.ts:639-648,726-736`).
- **State source completeness matters.** `stateGenerationSource` returns null if any drawn view is missing, empty or the wrong size. A calculator must not price a State from a partial source (`app/src/studio/stateGenerationSource.ts:21-59`).
- **Equipment repair and pose pricing use different grid planners.** Explicit repair uses `repairGridPlan` and its Tier 1 preference; an existing-move pose uses `repairGridLayout` at the 512 side limit; a planned imported-joint fallback uses `gridEstimate` with four columns. The same cells can price differently (`app/src/lib/items/items.ts:238-321,748-761`).
