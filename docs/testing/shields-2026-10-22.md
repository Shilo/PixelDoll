# Shield validation (2026-10-22)

Scope: `off_hand` shields on existing 4- and 8-direction rigs, idle and walk. No new bodies or motion were generated.

## Offline quality-gate fix

G9 treated every held silhouette as having a meaningful principal axis. A 5×6 mask becoming 6×5 keeps the same area and
most of its shape, but its calculated axis turns 90°. That caused a false failure and could spend credits re-rolling a
consistent round shield. Conversely, concentric filled and hollow masks could have the same calculated axis and escape
G9 despite a large shape change.

`axisOf` now returns no axis for a near-round mask: the covariance eigenvalue gap divided by their sum is below 0.2
(principal aspect ratio below √1.5). Those adjacent-frame pairs use the existing aligned-IoU floor of 0.3. Elongated
items retain the existing 30° limit relative to the forearm; the anchor route still uses IoU.

Three new Vitest regressions demonstrate:

- Near-round width/height variation passes instead of reporting a false quarter turn.
- A large round-silhouette change fails the shape check.
- An elongated item turning 90° against a stationary forearm still fails.

The first two tests fail before the fix and pass afterward. An additional keyless check on saved sword exports found
no G9 failures in 36 Ranger frames and 60 eight-direction frames (idle/walk, generated views).

## Offline body-occlusion follow-up

The follow-up used all **96 saved selected frames**, the stored skeleton-v3 keypoints and the original frozen bodies.
No PixelLab requests or generations were needed. The data-export browser blocked every remote request and WebSocket,
served source modules from a separate keyless localhost server, and recorded zero remote request attempts. It never
invoked `runItem`, re-submitted jobs, accepted drafts or changed the original source images.

Whole-mask area and PCA angle are unreliable when a shield passes behind the torso. A wrist-aligned comparison now
counts missing pixels behind the other frame's frozen body (1 px tolerance) as potentially hidden. It requires at
least six shared pixels, visible IoU at least the existing 0.3 floor, and body-hidden differences to account for at
least as many pixels as visibly unexplained differences. G5 additionally compares every frame with the largest
observed frame; adding only potentially hidden reference pixels must bring area CV below the existing clip limit.

This is **uncertainty handling, not proof of a correct shield**. Supported G5/G9 flags become explicit occlusion review
warnings, which do not trigger those gates' paid retries. Original metrics remain recorded, and neither masks nor
exported pixels change. G4 presence, body integrity, registration, border and handedness checks retain hard failures.
The policy applies only to posed held items with wrist tracks; it does not globally relax thresholds for shields.
