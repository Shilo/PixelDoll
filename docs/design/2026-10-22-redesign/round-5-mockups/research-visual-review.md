## Review gates

| Gate | Required visible result | Reject or revise when |
| --- | --- | --- |
| Immersive first impression | The world fills the frame and the character is the visual anchor. Typography and controls float in stable zones with local gradients. The empty chamber has quiet material depth. | The image first reads as a toolbar, card dashboard, browser layout, statistics page or bounded sprite viewport. A decorative world merely fills unused space around panels. |
| Exact character | Body and equipped layers come from actual stored sprites, composed deterministically, with nearest-neighbor enlargement. Existing painted shading remains. | Image generation redraws anatomy/equipment; pixels are tinted, blurred, lit, recolored by appearance, or softened to fit the environment. New character shadows, glow or shaders appear. |
| Desktop hierarchy | Character name/information sit left; equipment modes, categories, choices and actions stay together right; Preview / Top-down / Side-scroller remain top-center. The character occupies the remaining open world. | Equipment crosses both edges; the right region becomes a stack of unrelated cards; the character sits underneath controls; duplicate Play/Customize buttons appear. |
| Phone hierarchy | Character and useful world occupy the upper region. One stable bottom equipment sheet contains the wardrobe hierarchy; hit areas and text remain generous. | Desktop columns shrink into phone width; several floating panels compete around the actor; the sheet leaves only a narrow world sliver; scrolling affordances or safe-area clearance disappear. |
| Theme pair | Same product, layout and content; Porcelain is the chamber's light counterpart. Bronze is a restrained selection/action accent. Text and controls have stable local backing. | Light becomes an unrelated outdoor sunrise; decorative ground seams resemble focus/selection; a bright horizon cuts through the head; pale labels blend into Porcelain. |
| Game feeling | World scale, actor placement and camera-appropriate continuous ground communicate a place to try the character. Equipment is immediate and visually secondary. | Invented props, combat meters, joystick banks, debug grids, bounds or proof tools are added to make the view seem game-like. The character becomes a thumbnail beside a dense inspector. |
| Truthful state | Selected gear has a check/outline; real prompt/name and current stored coverage are respected. Notices are compact and anchored away from the actor. | A fallback image implies newly available animation/camera art; intentionally limited directions receive warnings; gear missing required coverage is shown misaligned; a large permanent error panel dominates the world. |

Any exact-character failure is a blocker. A correct sprite can still fail the immersive/composition gate: provenance does not make a dashboard feel like a game.

## Composition checks at delivery size

1. View every image at its intended display size before zooming. Read title, selected tab, item names and main action. Confirm long descriptions are collapsed to a deliberate disclosure line outside the creation form.
2. Compare desktop dark/light side by side: identical content, scale and hierarchy; only environment artwork and UI appearance change. Do the same for phone pairs. A better camera or emptier UI must not disguise a weaker theme.
3. Compare Preview/Top-down/Side-scroller at each size: identity, top tabs and equipment remain stable; only relevant inspection controls disappear. Character framing can change for the live camera.
4. Inspect the silhouette and held item against floor/horizon transitions. The UI's local gradients may strengthen reading areas, but no new actor shading/shadow may be introduced. A reflection, if used, must remain below the feet and subordinate; omit it on mobile live views.
5. Inspect thumbnail labels, selection checks and main-action text. Dark uses pale bronze fill with dark labels; light uses dark bronze fill with light labels. Quiet secondary text still needs enough contrast. The source palette calculations cover opaque pairs, not every generated background or gradient.
6. Check menu dots, overflow, close and disclosure cues remain touch-sized even when the glyph is small. Allow normal sheet/form scrolling, safe areas and a useful world gesture region. Static imagery cannot establish focus, pointer ownership or accessible gesture equivalence.

## What still images cannot establish

Do not report continuous movement, following camera, joystick cancellation, synchronized animation, autosave, cost confirmation, contrast compliance or resolver correctness as passed because the image looks plausible. The resolver requires separate implementation checks. Unexpected missing coverage may justify one unobtrusive example toast; it is not a requirement to show errors on all clean mockups. Temporarily hidden equipment remains equipped and restores when compatible; still images cannot demonstrate that lifecycle.
