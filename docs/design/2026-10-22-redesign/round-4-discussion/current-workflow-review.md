## Actual creation, review, save and animation order

1. Fill the separate New character form, then Create character. Connect is shown if needed; creation also checks account access. Drafts survive the connection detour (`CreateSheet.svelte:25–29`, `:52–56`; `state.svelte.ts:86`).
2. Progress is **Drawing your character → Setting up the skeleton → Animating idle and walk → Checking and saving** (`create.ts:36`). V3 supplies all eight original rest views; only the selected independent directions are animated; selected mirror directions are derived. Unselected originals are retained, not equivalent to completed animation coverage (`create.ts:169`, `:187`, `:233–236`).
3. Work can continue behind a hidden sheet, and persisted creation resumes on reload. Failure exposes Start over / Try again; retry uses a fresh seed and incurs new generation work (`CreateSheet.svelte:105`, `:114–119`; `state.svelte.ts:624–647`).
4. The result is **already saved on the device** when the completion review appears. Review shows walking in selected directions and quality notes. Its CTA is **Start dressing up**, not Save/Accept. Closing review does not discard the character (`create.ts:277`; `CreateSheet.svelte:71–85`, `:112–113`).
5. Dressing edits autosave; project switching flushes pending edits. Adding more animation is an explicit **Add a move** flow, with item posing costs and separate review for shared equipment fits (`state.svelte.ts:200`, `:279–295`; `Moves.svelte:61`; `MoveSheet.svelte:70–119`).

## Recommended challenges before new mockups

1. **Keep the creator separate and preserve its contract.** Carry the existing fields, prompt linkage, explicit mirror choices, cost and asynchronous progress into the new art direction. A simplified mockup must not erase the capabilities just added.
2. **Separate generation camera from world testing mode.** The proposed Preview / Top-down / Side-scroller tabs can describe inspection versus playable scenes. They cannot imply regenerating or converting the character's camera. Each character currently has one stored `rig.view`; its source images and animations were generated for that view (`create.ts:167–169`, `:218`, `:357`). A top-down-generated character does not gain a true side-camera sprite by entering a side-scroller world. Show available frames honestly and settle how incompatible/missing views behave before representing effortless switching.
3. **Do not add a manual Save step after creation.** Review follows saving, and dressing autosaves. Use selection → customization as navigation; treat Create character → background generation → saved-result review → Start dressing up as a separate flow.
4. **Make Preview retain inspection access.** All-direction comparison, transparent pixels, pause/frame stepping and quality notes matter to aligned layer output. Their controls can be compact or contextual without becoming extra world toggles. Top-down and Side-scroller can hide authoring controls while preserving equipment access.
5. **Keep Moves an authoring destination inside customization.** Playback move selection and paid Add a move are different actions. The three world/preview tabs should not replace the existing animation management or hide its price/review implications.
6. **Design actual data states.** Selection needs first visit with demo only, many saved characters, import, returning to last project, background generation, failures, and just-completed work. Customization needs a bare new body and empty equipment categories as much as a dressed demo. Do not make the selection cast a fixed storage limit.
7. **A no-splash selection flow still needs account and cost access.** Let the demo, saved characters and import remain usable immediately, with Create character prominent. Keep Connect/account balance and Activity available from the shell, and keep the quoted creation cost beside the spending action. Connecting is a contextual detour that preserves the form; a Free/Trial account has limited tool access and does not unlock the character-creation rig pipeline (`state.svelte.ts:86–99`; `ConnectSheet.svelte:49–54`). The current displayed default creation estimate is approximately 57–75 gens, not a free first character, and varies with size and independent directions.

The full-screen Obsidian Holodeck, left information, right equipment, and phone bottom sheet remain coherent. The main planning correction is to anchor that shell to the app's existing creation and storage behavior, then define the three proposed viewing modes precisely.
