# Production control inventory for the owned theme showcase

Date: 2026-10-23. Source audit of the current production Studio; no runtime or paid API calls. This is a coverage plan, not a claim that the owned theme or accessibility fixes have shipped.

## Boundary and recommendation

Production is `app/src/studio/`, mounted by `app/src/App.svelte:5`. The `app/src/ui/M1–M5.svelte` pages are development harnesses, dynamically imported only in development (`App.svelte:7`). Their controls should not inflate the current production inventory.

Build the showcase from three layers: shared CSS recipes, real behavior primitives, and representative domain composites. Actual lightweight behavior primitives already include `Sheet`, `Help`, `ApiPeek`, `RequestFields`, `Sprite`, and `SizePreview`. Buttons, fields, segments, notices, progress and rows largely remain classes in `studio.css`; a new Svelte wrapper for every class is unnecessary. Components tied to live stores or queue actions need inert showcase data and guarded actions; importing a paid workflow merely to obtain its appearance is not safe fixture design.

The foundation's Scene / Floating / Work roles are a proposed showcase contract. Current production uses the older opaque blue theme. Current production radii are **6 / 10 / 14 px** (`studio.css:8`); the approved owned theme target is **8 / 12 / 16 px**. Keep that distinction explicit in comparison evidence.

## Existing behavior worth retaining and independently reviewing

- `Sheet` uses browser modality, records the opening element (or project-menu trigger), restores it on teardown and conditionally focuses the first text input on fine pointers. `cancelDisabled` also sets `ui.sheetBusy`. Its actual center/bottom/side choice comes from `ui.size`, so examples must exercise those sizes rather than only resize a fake card.
- `ApiPeek` is a **nonmodal** native auto popover with `role="dialog"`; it focuses Close on open, restores its trigger and stops Studio shortcuts. It currently traps Tab at the first/last control (`ApiPeek.svelte:69`). The showcase must expose the real behavior and flag the foundation's requested focus-policy review rather than describe this as completed accessibility.
- Creator tabs implement roving tab stops, arrow/Home/End, associated panels (`CharacterForm.svelte:36`, `:83`). Other choice groups use Studio's general delegated keyboard handler (`Studio.svelte:102`). Do not derive keyboard contracts from shared visual class names.
- Production field errors are usually summary notices, not field-level associations. Creator displays the first `draftErrors()` message in a status paragraph and disables Create. `characterConfig.ts` validates body 32–256 in 4 px increments, padded frame minimum through 256, direction/mirror validity, safe numeric seed and prompt. Pending/retry semantics and paid-request authorization belong to workflow code and must stay intact when styling changes.
- Help is positioned in ordinary fixed stacking at z-index 200, while native dialog/popover use the browser top layer. Tooltip inside a sheet and tooltip near API popover should be tested for clipping/stacking; a large z-index alone is no proof.

## Prioritized showcase plan

1. **P0 — foundation/state wall:** both appearances, Scene/Floating/Work surface samples over a representative moving-world backing; type; all button recipes and sizes; text/number/password/textarea/select; switches/checks; choice states; notice/badge/progress; default/hover/active/focus/selected/disabled/busy. Show proposed invalid and read-only styling as explicitly labeled contract additions, not existing Studio behavior.
2. **P0 — behavior proof:** real `Sheet` with long form and fixed footer in center/bottom/side variants; actual `Help`, `ApiPeek` and `RequestFields` with inert sanitized values. Include edge placement, close/focus return and keyboard escape paths. A screenshot cannot prove keyboard behavior.
3. **P0 — domain proof:** real or markup-faithful creator section with linked prompt tabs, body/frame/presets/camera, size guide and compass/mirror joins; one equipment row and tile showing selected/equipped separately; a source-authentic palette ramp/color input; playback toolbar and full-width narrow adaptation.
4. **P1 — difficult workflow states:** design card list (including confirmation), import file/library preview/error, five export engine cards plus dense file details, actionable queue failures/follower/lost, quality review with long reasons/hard gate, busy dismiss-protected sheet, toast/offline/stage note.
5. **P1 — geometry and environment checks:** narrow 320/375/390 portrait, short landscape, desktop, zoomed text and long content; coarse-pointer sizes; reduced motion/transparency/forced colors/contrast and filter fallback. Exercise one scrolling sheet with nested disclosure and a popover opened from its footer. Keep focus rings visible near clipping boundaries.

Coverage can be represented as a compact matrix with one example serving multiple workflows; it should not become another production app or duplicate every form. The rule for additions is evidence from a real workflow plus a shared contract owner.

## Explicitly outside current production inventory

No production range slider, drag/drop uploader, native radio input, mixed checkbox, read-only text field, inline `aria-invalid` association, calendar, rich text editor, arbitrary dock/window manager or general data grid was found. The only range is development M4 zoom (`app/src/ui/M4.svelte:263`); the only drag/drop importer is development M2 (`app/src/ui/M2.svelte:347`). A range, read-only, or invalid-field recipe may be useful for the foundation target, but must be identified as a proposed recipe. The real activity ledger is a simple read-only table, not an interactive data grid.

## Verification limits

This report is based on source inspection and repository instructions. It establishes real uses and candidate coverage, not measured contrast, visual parity, runtime accessibility, mobile comfort or performance. No endpoint requests, tokens, environment contents, generated images, production code edits or commits were involved.
