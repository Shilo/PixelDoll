# Adversarial review of the app bars contract

Revise the draft before implementation. Keep the fixed trailing X, pinned global actions and secondary-before-primary order. Specify the consequence of each exit, the narrow-width fallback and the return destination for interrupted flows. The draft and mockup disagree on running moves, available footer slots and label wrapping. [Draft](plan.md) · [Mockup](mockup.html) · [Main proposal](sol-research.md) · [Competing proposal](deepseek-research.md)

## Eight decisions

1. **Header X. Agree on the icon and position. Disagree with relying on the icon alone to communicate consequences.** Closing after a paid request starts must leave recoverable work in Activity. Closing during a tab handoff or account check can abandon an intent that has yet to start. Closing Rename, Slots edit or a prepared Frames review can drop local input. Keep the localized Close name and 44 px logical-end target. Put “Continues in Activity” beside actual progress and provide a persistent Activity entry. Preserve recoverable drafts where feasible and use a Keep editing / Discard changes alert when a deliberate exit would lose meaningful input. Back from Frames review should preserve the prepared state or disclose what it clears. Route X and Escape through the same close request. Let browser Back walk an actual prior pane before requesting root exit. Suppress backdrop dismissal for unpreserved edits and consequential choices. Keep a disabled X in place and announce progress during an atomic write. Today browser Back can directly clear the sheet, and the Frames close callback resets the prepared review and stays in the sheet. A button replacement alone leaves both paths inconsistent. 2. **Retiring Hide, Later, Not now and Done as duplicate dismiss buttons. Agree. Preserve distinct decisions.** Create's Keep working and Move's and Setup's footer Hide duplicate the header callback. Remove them after moving continuation copy next to progress. Setup's failed-run Cancel clears the attempt through dismissSetup. Rename it Dismiss failed setup and keep it separate from Close. Move review's Discard draft must remain distinct from X, which leaves the checkpoint recoverable. Connect's Not now also abandons a deferred spending action. Keep that cleanup on every actual exit, including before the lazy component mounts. Tell the user that the request has yet to start. Activity's new body Cancel request must be able to cancel the tab handoff in place. Studio currently cancels the waiting click on any exit from Activity. Preserve that safety property unless a separate decision changes it, and disclose the effect in the waiting message. The connected account view and Item Details can replace Done with X where the callback just leaves applied work. 3. **Never stacking phone footers. Disagree.** At a 320 px viewport, the mockup's 300 px phone sheet leaves 268 px for two buttons after padding and gap. That is 134 px per button before button padding and icons. Frames can pair “ZIP herunterladen” with “Bearbeitete Dateien importieren.” Production's centered alert leaves about 240 px for both buttons at 320 px. The mockup sets white-space to nowrap and a fixed 44 px height. Its phone flex container can wrap whole buttons by accident, and its standard sheet and alert rows can overflow. Use a two-column row when both labels fit on one or two lines, with a 44 px minimum height, normal text wrapping and shrinkable tracks. At the narrow action-bar breakpoint, stack in the same DOM and visual order: secondary first, primary last. Keep the note above, the body scrollable and actions reachable with safe-area insets, zoom or a software keyboard. Use the same fallback for centered alerts. Replace the competing proposal's primary-first stack and illustrate actual German labels. 4. **Moving Reset all and the Export Settings opener into the body. Agree with conditions.** Settings already has a compact root Reset all, page-scoped Reset and Forget controls, and a reset search result and confirmation. Put one Reset all row at the end of the Settings index across widths. Keep its search entry, scope-specific actions and busy/error feedback. Put Export settings near the top of Export alongside format/preferences, and restore focus to that row and retain export state on Back. Cover Export → Settings (Export) → All settings, Settings (Export) → character Export, and Settings (PixelLab) → Account or Activity. Existing close callbacks return to the parent in several paths. If X means exit the entire task, give nested children explicit Back and preserve the destination, section and opener separately. Desktop Settings uses sibling navigation in a split view, while compact Settings drills into a pane. More opening Settings, Activity or Connect must preserve the draft and presented result. The draft is currently local with a special formDrafts bridge around Connect. Assigning the sheet clears createPresentation.id and can remove a completed attempt from presentation. Move ownership of the draft, presentation and return route above child overlays before lifting the UI. Preserve paid enhancement and generation continuation guards. On genuine departure, park running work and apply the defined draft exit policy. Resolve the Full screen exception explicitly: keep its slot and expose an unavailable state with an accessible explanation where the API cannot act, including manifest fullscreen. 7. **Inserting Activity at the start of the trailing group. Disagree.** End anchoring protects controls on its right, but adding width changes name space and the view switch's measured clearance from the stage center. The current indicator also covers queued jobs and stopped work needing attention. Reserve a fixed-width Activity control on wide layouts, with idle, active and needs-attention states within it. On compact layouts, use the existing Activity row in More plus an indicator contained inside More's fixed box, with equivalent accessible status and a persistent recovery entry. Keep the existing breakpoint-based overflow, including access to Mount. Reserve each direct Undo/Redo slot independently with visibility hidden for empty stacks. Disable hidden buttons and hand off focus if the focused action exhausts its stack. Define stable geometry within a breakpoint, including changes in Activity counts.
