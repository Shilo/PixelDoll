# App bar code review

Static review of the working diff and new studio files. No tests or browser checks were run.

## P1

1. **Completing a creation while Settings or Activity is open drops its result screen.** Start a character, open More → Activity, let the run finish, then choose Back to New character. Switching sheets clears `createPresentation.id`. Completion checks only that ID and removes the attempt when it is empty, so `returnToCreator()` can no longer present the result. The character is saved in the library, but the user comes back to a form instead of the result and its Start dressing action. `app/src/studio/state.svelte.ts:288`, `:315`, `:3681`.
2. **Browser Back can destroy a prepared review underneath the Discard alert.** Prepare replacement frames or stage an import, click X to open Discard changes, then use browser Back. The sheet remains the registered exit owner, and its Back callback bypasses the `discarding` guard. That callback resets the prepared data while the alert stays open, so Keep editing cannot recover it. Native Escape reaches the foreground alert correctly. `app/src/studio/sheetExit.ts:21`, `app/src/studio/Sheet.svelte:68`, `:81`, `:152`, `app/src/studio/FramesSheet.svelte:127`, `:224`, `app/src/studio/ImportSheet.svelte:181`, `:410`.
3. **Export and creator tests still target removed controls.** The first three runs in the overlapping-creations test click Close on a creator screen that only has Back. The same test later clicks Cancel on a dirty creator, which now needs Back followed by confirmation. Export tests still look for Close export and exact Back even though the new labels are Close and Back to Export. The Settings round trip also expects Escape to return from Export to Settings and later clicks a Settings row that is hidden for an Export opened from Settings. These locators and expectations fail before exercising the intended behaviors. `app/test/e2e/character-creator.spec.ts:115`, `:135`, `:143`, `app/test/e2e/export-picker.spec.ts:1531`, `:1627`, `:2085`, `:2089`.

## P2

4. **A visit to Settings makes previously typed creator text exempt from discard confirmation.** Enter a name or description, open More → Settings, return with Back to New character, and immediately use the creator's Back. Remounting treats the restored draft as the initial comparison value, so the creator exits without prompting and the text is gone on the next open. Opening Settings and using its X instead leaves the draft in `formDrafts.character` after both screens close, so a later Create from scratch unexpectedly revives it. A successful account connection opened from the creator's More also exits both screens because `connected()` clears `ui.sheet` when there is no spending continuation. `app/src/studio/CreateSheet.svelte:53`, `:59`, `:63`, `:213`, `app/src/studio/state.svelte.ts:314`, `:590`, `app/src/studio/ConnectSheet.svelte:119`.
5. **Frames Back discards the review even without an alert.** Stage valid replacement frames and use Back from the review. The callback clears `prepared`, so the only route back to the review is to import and prepare the files again. The approved Frames flow calls for Back to preserve that review. `app/src/studio/FramesSheet.svelte:127`, `:224`.
6. **Export opened through Settings loses an available navigation route.** Open Settings → Export → Export this character. The Export settings row is now conditional on `!settingsNavigation.exportOpen`, so the picker loses its previously available Settings opener. Its X and Escape now leave both layers. Back remains the route to the previous sheet, but it resets `fromExport` and remounts Settings, including when the previous page was the Settings view opened from the original Export picker. `app/src/studio/ExportSheet.svelte:773`, `:794`, `app/src/studio/settingsNavigation.svelte.ts:90`, `:95`.
7. **History focus has no usable fallback on midsize phones.** At 500 px, focus Undo with the keyboard and use the last undo step. Undo becomes hidden and disabled. Redo becomes enabled but stays `display: none` at this width, so `step()` attempts to focus a hidden target and never sends focus to More. `app/src/studio/Toolbar.svelte:125`, `:264`, `app/src/studio/experience/layout.css:270`, `:301`.
8. **The creator drops the Activity cue.** On a phone, start a creation and stay on New character. The ordinary toolbar supplies job state to `GlobalActions`, but its controls are inert under the creator. The creator's `GlobalActions` receives no job state and its More button has no dot while the run is active or needs attention. On wide screens, Activity's empty button reserves its intrinsic idle width only, so a sufficiently wide count expands the slot and moves the preceding controls. `app/src/studio/Sheet.svelte:150`, `app/src/studio/Toolbar.svelte:313`, `:328`, `:331`, `app/src/studio/GlobalActions.svelte:8`, `:18`, `app/src/studio/experience/layout.css:80`.
9. **Typed creator input can bypass the guard on the first visit.** Enter only an Advanced seed and use Back, Escape, or browser Back. The dirty comparison reads only name, details, and prompt, so the typed seed is lost without confirmation. `app/src/studio/CharacterForm.svelte:664`, `app/src/studio/CreateSheet.svelte:55`, `:213`.
10. **The Reference picker and API calls panel retain separate chrome.** Open a frame reference picker and there is no visible title or Close button. Open API calls in Developer mode and its existing header uses a separate close control named Close API calls and gives that control initial focus. Share also newly starts on X in its default preview state because the generic popover focus helper picks the first enabled button. `app/src/studio/ReferenceField.svelte:229`, `app/src/studio/ApiPeek.svelte:163`, `:412`, `:454`, `app/src/studio/SharePopover.svelte:245`, `:317`.
11. **Some sheets still put artifact or dismiss actions in the footer.** Running Add move puts Queue another and the progress note in the footer. Its completed Done action dismisses the run and closes the sheet. Running Create also leaves its note in a footer. None connects the running message to the exit control. The Frames picker still puts Restore and Download in the footer, and failed Setup uses a generic Discard button in the footer where the contract specifies Dismiss failed setup in the body. `app/src/studio/MoveSheet.svelte:1304`, `:1373`, `app/src/studio/CreateSheet.svelte:425`, `app/src/studio/SurfaceHeader.svelte:45`, `app/src/studio/FramesSheet.svelte:426`, `app/src/studio/SetupSheet.svelte:235`.
12. **Backdrop clicks follow different rules from the contract.** An outside click dismisses the consequential Discard changes alert because `ConfirmDialog` registers backdrop dismissal whenever it is open and only checks whether it is busy. The PWA installation dialog responds to X and Escape and has no backdrop handler. `app/src/studio/ConfirmDialog.svelte:42`, `:61`, `app/src/studio/PwaRuntime.svelte:171`.
