A visible Close or Cancel in the tab sequence is strongly recommended. Least-destructive initial focus is appropriate for hard-to-undo actions. Use one reading order across browsers and input types. PixelDoll already uses safe-first/commit-last in `ConfirmDialog`, several paid review footers and Export. Rightmost commit extends that existing convention and matches the progression from Back to Next, with enough familiarity from Apple, Material and Primer. Give the safe option initial focus in consequential alerts so action position never makes destructive activation the default. Use top-right X for safely dismissible task surfaces, legible text for decisions, and leading Back only when there is a real previous view. The sources support tradeoffs among those choices and do not establish a universal web standard.

## Proposed layout contract

Left and right mean logical start and end. Preserve DOM and visual order through localization, narrow widths and zoom. Keep control targets at least 44 CSS px in primary bars. Allow wrapping of titles and action labels inside their own regions. Use the existing task-sheet presentation breakpoints: centered on desktop, bottom on compact portrait, trailing in short landscape. Keep confirm alerts centered at every size. Keep sheet header and nonempty footer fixed within the surface while the body scrolls. If short landscape or the software keyboard makes that layout unusable, let the surface scroll so both bars remain reachable.

### Interaction and placement

- **Vocabulary.** Back returns to a prior pane or screen, preserving edits. Close names the sheet X. Cancel is the safe footer decision in alerts, with Keep generating when Cancel generation is the other choice. Use Continue for a next step, Save for a write, and task verbs such as Create character, Import character, Start dressing, Download ZIP, Replace frames, Discard draft, Delete and Stop generation where those consequences apply. Use Done only when it acknowledges completion without also standing for save, cancel or discard. Keep data-backed names, prices, scope and existing opener cues localized.
- **Footer order.** Keep the secondary action immediately before the primary when they form a decision. In tight widths stack in that same order, with the primary last and focused controls fully visible. Cost/condition text precedes the actions and is associated with its button. A third action belongs with the content it affects, such as Download backup beside the file details or Discard draft in a distinct recovery section. Preserve the two-stage bulk delete safeguard. The footer and X must have distinct effects when both exist. Remove redundant Close, Hide and Keep working buttons if the header X performs the same safe exit. A footer Cancel that deletes a failed attempt becomes Discard draft or Dismiss result according to its actual effect.
- **Steps.** Put chevron + Back top-left only after entry to a distinct pane. Move Export's Settings opener and Settings' Reset all into their appropriate body sections. Export > Settings back returns to Export. Settings > Account or Activity back returns to the initiating Settings pane. X exits the whole current task to its external caller. In a prepared Frames review, Back returns to Fix frames, while X requests exiting Fix frames and asks about any edits that would be lost. Browser Back walks one step when one exists, or requests a root exit. Restore heading or retained control focus on transitions and keep prior answers. Tabs switch sibling modes and never manufacture a Back step.
- **Busy.** For an atomic local save, critical apply or irreversible update stage, keep the X/Back targets in place and disable blocked actions. Route Escape, browser Back and backdrop through the same leave guard. Keep the dialog open, announce progress in a live status, and restore controls on failure or settlement. For a queued or running generation, leave X and Back enabled when the job persists. Show “Continues in Activity” near progress. Put Stop generation or Cancel request in the relevant job controls with explicit consequences. Account verification that may gate a paid continuation must clear that intent when the user exits.
- **Global actions.** Every screen uses the same Full screen and More pair at the trailing edge, including creation, progress, failed creation and success. Full screen remains conditional on browser/installation capability as today. Render More with a screen-aware action list. Locale, help and compatible preferences can be used with the creation draft intact. Commands that navigate away or start incompatible work run the current screen's leave guard first. If the command opens a true modal, keep focus inside it and return to the invoking screen on close. A modal temporarily owns interaction. App-wide commands are available again on dismissal, and the browser retains its own exit-fullscreen action while a modal is open.
- **Toolbar width and history.** Keep Full screen and More pinned, with geometry derived from existing layout. Characters retains New and Customize retains Export as its direct task action. Prioritize screen name and view controls. Preserve the existing compact overflow order for Redo and Share, then Random look, then Undo. Move the conditional Activity shortcut into More on compact rows where it competes with the pinned pair, retaining the Activity row and an accessible pending indicator on More. Each Undo/Redo slot present at the viewport breakpoint uses `visibility: hidden` independently when its stack is empty. Retain the element and its inline size/gap, mark its button disabled, and make sure its label or tooltip cannot become a hidden focus stop. If a focused history action consumes its stack, move focus to the available counterpart or More without scrolling. Overflow menu rows can omit unavailable commands and empty separators because they do not control toolbar geometry. Focus continuity still applies if a menu remains open.
- **Exit arbitration.** An Escape press reaches one owner: active inner popover, top alert or active sheet; the browser retains precedence when it consumes Escape for fullscreen. Freeze background shortcuts and selection within a native modal. Backdrop is a completed outside click on eligible task sheets only. Retain click-through protection. A grabber needs a matching gesture; omit it for a purely decorative modal sheet. Avoid adding a swipe shortcut to dirty forms as part of the first implementation.
- **Focus and feedback.** Preserve reliable opener capture/restoration, including visible fallback triggers when switching layouts. Sheet initial focus goes to a short form's first useful field or to the heading for long/structured or compact content where opening the software keyboard would obscure context. Announce saving, invalid state and errors close to the relevant control. Use `aria-labelledby` for a unique dialog title, `aria-describedby` for short alert consequences, and actual menu keyboard semantics for command-only menus. Avoid tooltip-only explanations and automatic focus on a paid or destructive command.
