# Studio panel design plan

PixelDoll’s customization panel should collapse completely and return the space to the stage. Keep it open on first entry to Preview so people can find Wardrobe, Colors, Outfits, Moves, and States. Give people one visible control to open and close it. On compact touch screens, entering either Live View should temporarily start with the panel closed. Returning to Preview restores its prior visibility and editing context.

[Try the interactive prototype](sidebar-lab.html). Select a viewport, switch between Preview and the Live Views, then reopen the panel. Change the dock side on a side-by-side layout. To compare approaches, reopen the panel in a Live View and select **Overlay** or **Separate controls area**. The prototype uses PixelDoll’s shipped demo art and models placement and controls. Its game controls illustrate their footprint.

## Interaction

| Situation                                                                        | Panel behavior                                                                                            |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| First visit after a page load                                                    | Preview opens with the editor visible.                                                                    |
| Manual toggle in Preview                                                         | Show or hide the editor. Keep the choice in memory for the page session.                                  |
| Preview to Top-down or Side-scroller on a compact touch screen with auto-hide on | Start this visit with the panel hidden. Keep a visible Customize button.                                  |
| Reopen or close during that Live Views visit                                     | Honor the manual choice through switches between Top-down and Side-scroller, rotation, and input changes. |
| Return to Preview                                                                | Restore the Preview tab and its browse position. Restore Preview visibility if this visit used auto-hide. |
| Enter a Live View on a roomy viewport or with auto-hide off                      | Carry the current visibility across views. Manual changes continue to apply across views.                 |

Treat a visit as one trip from Preview into either Live View and back. Resolve automatic collapse on entry, using the existing compact layout and the touch context of the activation. Compact includes the bottom-sheet layout and short landscape. Use primary coarse input as the default for keyboard or assistive activation on phones. A mouse opening a narrow window on a hybrid should retain its panel. Reevaluate eligibility on the next visit. Resizing, scrolling, mouse movement, and the first touch on the playfield should never trigger an automatic visibility change.

Save two preferences in local app settings, scoped to the browser and independent of character data.

- **Settings → Appearance → Panel side** offers **Left** and **Right**, with **Right** selected by default. This preference applies to side-by-side layouts. Portrait bottom sheets keep their position. A side preference controls panel placement. The Attack, Jump, Sprint, and Mount cluster keeps its position relative to the stage and uses the existing safe-area rules.
- **Settings → Live Views → Hide panel when entering Live Views** defaults on for eligible layouts. Supporting text names the scope and recovery: “On compact touch screens. Open it anytime with Customize.” A preference change applies on the next visit.

Keep the selected tab, browsing offset, and panel visibility in the current Studio session. Equipment and other character edits continue to save under the existing rules. If Moves or States is selected in Preview, Live Views can show an available tab while Preview keeps the original selection and offset.

## Layout and control

| Space available             | Open                                                                                                                                                                                                    | Closed                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Desktop and roomy landscape | Dock a scrollable panel on the selected side. Put the toggle on the same side of the toolbar, near the panel.                                                                                           | Keep the button anchored and give its column to the stage.                       |
| Phone and tablet portrait   | Keep the nonmodal panel below the stage. Put the toggle in the existing view row, away from the touch actions and without taking room from the character-name row.                                      | Keep the same button in the view row. Return the panel’s height to the stage.    |
| Short landscape             | Dock at the selected side while the stage and editor can both fit. Use the side-dock placement of the toggle.                                                                                           | Return the width to play. Leave the mode switch and reopen control within reach. |
| Very short or zoomed window | If neither split fits, use the area below the header for an independently scrollable editor. Keep the toggle and view switch visible, with the covered stage unavailable to keyboard and pointer input. | Give that area back to the stage.                                                |

Use Bronze’s outline action, a Lucide panel icon that points toward the dock, and a target of at least 44 CSS px. Show **Customize** when closed and **Hide panel** when open. Reserve the longer of the two localized labels to keep the action in place. On crowded single-row toolbars, use the icon with a tooltip and an accessible name for the current action. Use the icon-only treatment only where the name, view switch, and existing actions cannot all fit with the label.

Use one native disclosure button, `aria-expanded`, and `aria-controls` referencing the retained panel. Keep the panel nonmodal in split layouts, with no scrim. The tablist uses its current keyboard navigation. Collapsed content leaves the tab order and accessibility tree. Keep focus on the toggle for keyboard activation, and return focus to it when a focused panel child disappears. Preserve the application’s existing handling of Escape, dialogs, item menus, and game input. The view buttons and launcher stay available under reduced motion.

## Why the alternatives lost

| Approach                                                               | Useful when                                                              | Result for PixelDoll                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Manual collapse only                                                   | Desktop and larger tablets where editing and scene play fit together     | Predictable, but requires the same extra tap whenever a phone user switches from editing to play. A one-time collapse on compact Live Views entry keeps control with the person during play.                                                                                                                                                                                                                                                |
| Automatic collapse while a thumb is held, or on every live-mode change | The playfield is always the only task                                    | Moves the target area during a gesture or undoes a deliberate reopen. Apply the rule once per visit.                                                                                                                                                                                                                                                                                                                                        |
| Always leave a narrow strip of tabs or a grab handle                   | Tabs are destinations with useful one-action access in the compact state | Keeps consuming the most constrained dimension. In landscape, a 44 px strip is 18% of the existing 240 px stage width at 568×320. Gesture-only handles are easy to miss and compete with scrolling, zoom, and movement. A named button can use space already reserved for controls.                                                                                                                                                         |
| Floating overlay, with the controls over or under it                   | A short tool needs to stay near an unobscured part of the scene          | A bottom or right overlay intersected the touch cluster in all three phone trials. Putting the buttons above it trades blocked editing targets for blocked play targets. A gradient and scroll padding can improve legibility and reveal later rows. The shared pixels still have two possible input owners. A left overlay avoids the resting Attack cluster in wide enough landscape, but still covers movement space and the live scene. |
| Reserve a separate strip below the panel for the touch controls        | A tall viewport can afford permanent play chrome                         | The measured cluster is 174×182 px. A 194 px band including the existing 12 px inset fits the 390×844 prototype at the cost of a 174 px-high stage. At 844×390, only 144 px remain below the bar and above the band. At 568×320, the existing view row leaves 34 px there. Both are below the current 200 px usable sheet minimum.                                                                                                          |
| Modal editor as the normal mobile presentation                         | Editing is a protected decision with an explicit end                     | Wardrobe, color, and outfit changes are judged against the character as people work. Split editing keeps both available. The single-pane fallback is useful only when a split cannot fit.                                                                                                                                                                                                                                                   |

VS Code and Blender demonstrate independent visibility controls for editing panels while keeping the principal work area available. Apple’s sidebar guidance concerns navigation, whereas this panel edits the current character. Android’s standard sheet and NN/g’s mobile studies provide better analogies for docked, nonmodal access and explicit dismissal. WAI’s disclosure pattern supplies the button semantics, and WCAG explains visible focus and a non-drag path. ## Evidence and tradeoffs

The running Studio was measured at 15 viewport sizes, from 320×300 to 1920×1080, including both sides of the 600 px width cutover and portrait tablet sizes. These are the current open stage dimensions and the available space after removing its panel reservation, using the original header and view-tab heights. A production adjustment for a 44 px second-row target may use 4 px of the projected stage height.

| Viewport | Current stage | Stage with panel reservation removed |
| -------- | ------------: | -----------------------------------: |
| 320×568  |       320×265 |                              320×476 |
| 390×844  |       390×372 |                              390×752 |
| 568×320  |       240×228 |                              568×228 |
| 844×390  |       512×338 |                              844×338 |
| 768×1024 |       768×463 |                              768×924 |
| 1024×768 |       672×708 |                             1024×708 |
| 1440×900 |       929×840 |                             1440×840 |

At 320 px, a temporary text-only Customize action measured 91 px in the real top bar. It reduced the character-name control from 81 px to 37 px. The prototype places its 44 px-high labeled button beside the view switch under that bar. Landscape provides the remaining width to the scene when the panel closes. At 568×320, the real touch cluster already occupies 182 of 228 stage pixels vertically. The existing app moves the cluster to the end of the available stage, which keeps every action reachable under auto-hide opt-out.

The browser prototype passed 32 layout combinations (eight sizes, two themes, two dock sides) and eight view-switch sequences. Checks covered a stationary activation target, panel and stage separation, touch-target sizing, left and right docking, restoration of the Moves tab, scroll and keyboard focus, manual override across the two Live Views, and a previously closed Preview. The 14 existing `experience-parity` cases also passed against the Studio, including simulated touch movement and Attack-stick input.

The implementation takes four extra pixels for the phone toolbar from the bottom sheet where space permits. This preserves the existing character fit at 390 × 844. In windows such as 320 × 240, the live action cluster switches to a row with a smaller Attack stick and 44 px buttons, leaving the view switch and panel toggle clear. Browser checks covered the toolbar in all ten locales at 320 px and the longer labels during language changes on desktop. Physical device and screen reader testing remains open.

## Implementation and acceptance

1. Put the explicit session visibility and Live Views visit state beside the Studio experience state. Store only the side and auto-hide preferences through existing validated local preference and reset behavior. Wire the settings search terms and localize both actions. Keep the existing per-character animation settings independent.
2. Let the shared geometry compute the rail side, panel reservation, and very-short-window fallback. Use its bounds for the character, world, backdrop gradient, playback, zoom, game controls, and notifications. Fit the scene once per intentional layout change. Keep explicit zoom and world position during a pure panel toggle. Cancel pending gestures on a layout change so their targets cannot jump under a held finger. If a panel reveal needs motion, use the Bronze duration and disable it for reduced motion.
3. Retain the mounted customization content or explicitly restore its scroll. Preserve tab and focus on hiding, showing, and reorienting. When the panel goes away, direct its pending-job status to the existing More indicator.
4. Extend the existing geometry and Studio browser coverage for the new state transitions and placement. Verify at 320×568, 390×844, 568×320, 844×390, 768×1024, 1024×768, 1440×900, and a very short window in both themes. Check the real touch cluster with a left dock and with auto-hide off. Exercise keyboard order, nested popovers and dialog dismissal, focus restoration, gesture cancellation, safe areas, long localized labels, and 200% browser zoom. On physical phones, verify two-thumb movement and attack, rotating mid-visit, and reopening while using VoiceOver or TalkBack.
